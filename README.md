# FORMA — интернет-магазин одежды

Курсовой проект по МДК 02.01 «Технология разработки программного обеспечения». Проект подготовлен по заданию из исходного документа: тема — разработка web-сайта для магазина одежды; язык — JavaScript; среда — Visual Studio Code; платформа — Web; СУБД — PostgreSQL.

## Что реализовано

- адаптивная главная страница с акцентом на коллекцию одежды;
- каталог из восьми демонстрационных товаров;
- фильтрация по категориям, отдельный фильтр новинок, поиск и сортировка;
- добавление товаров в корзину, изменение количества и удаление позиций;
- избранные товары, состояние корзины и избранного сохраняются в браузере;
- форма оформления заказа с проверкой обязательных данных;
- REST API на Node.js и Express;
- PostgreSQL: таблицы товаров, заказов и состава заказа;
- создание заказа в транзакции с проверкой размеров и остатков на складе;
- автоматическое уменьшение остатка товаров после успешного заказа.

## Запуск в Visual Studio Code

Требуются **Node.js 18 или новее** и **PostgreSQL**.

1. Распакуйте архив и откройте папку `clothing-store-coursework` в Visual Studio Code.
2. Создайте в PostgreSQL базу данных с именем `forma_store`. Это можно сделать в pgAdmin: правой кнопкой на «Базы данных» → «Создать» → «База данных…».
3. Откройте Query Tool для базы `forma_store`, загрузите файл `db/schema.sql` и выполните его. Он создаст таблицы и добавит восемь демонстрационных товаров.
4. Скопируйте `.env.example` в новый файл `.env`. Укажите реальные `PGUSER` и `PGPASSWORD`, а при необходимости — адрес и порт PostgreSQL.
5. Откройте терминал VS Code в папке проекта и выполните:

   ```bash
   npm install
   npm start
   ```

6. Откройте в браузере адрес `http://localhost:3000`.
7. Проверьте работу базы по адресу `http://localhost:3000/api/health`: при успешном подключении ответ будет `{"status":"ok","database":"connected"}`.

Для разработки с автоматическим перезапуском сервера можно использовать `npm run dev`.

## Демонстрационный просмотр без PostgreSQL

Для просмотра дизайна откройте `public/index.html` в браузере: каталог и интерактивная корзина будут работать на тестовых данных. Однако оформление заказа, сохранение заказов и загрузка каталога из БД требуют запуска сервера и подключения PostgreSQL. Для полноценной проверки проекта используйте инструкции выше.

## API

| Метод | URL | Назначение |
|---|---|---|
| GET | `/api/health` | Проверка доступности PostgreSQL |
| GET | `/api/products` | Получение каталога; поддерживаются параметры `category` и `search` |
| POST | `/api/orders` | Проверка данных и создание заказа с позициями в транзакции |

Пример тела запроса `POST /api/orders`:

```json
{
  "customer": {
    "name": "Иван Иванов",
    "email": "ivan@example.com",
    "phone": "+7 900 000-00-00",
    "address": "Москва, ул. Примерная, д. 1",
    "comment": "Позвонить перед доставкой"
  },
  "items": [
    { "id": 1, "quantity": 2, "size": "M" }
  ]
}
```

## Примечания

- Фотографии загружаются по внешним URL, поэтому для их отображения требуется интернет-соединение.
- Сейчас реализован демонстрационный каталог. Цены, описания и остатки можно изменить в таблице `products`.
- На сайте не подключён платёжный провайдер: форма создаёт заказ в базе, а способ оплаты и доставки согласовывается с покупателем.
- Политика конфиденциальности, рассылка, ссылки на соцсети и часть информационных ссылок представлены как демонстрационные элементы; перед реальным запуском магазина их нужно связать с соответствующими сервисами и документами.


## Публикация в интернете (Render + Neon)

Для учебной демонстрации можно разместить Node.js-сервер на Render, а PostgreSQL — на Neon. Render выдаёт публичный адрес `onrender.com`; бесплатный веб-сервис может засыпать после периода бездействия, поэтому первый запрос иногда открывается не сразу. Бесплатная база Render имеет срок действия 30 дней, поэтому в этом проекте инструкция рассчитана на Neon.

1. Создайте проект PostgreSQL в Neon и откройте SQL Editor.
2. Скопируйте содержимое `db/schema.sql` в SQL Editor и запустите запрос, чтобы создать таблицы и демонстрационные товары.
3. В Neon нажмите **Connect** и скопируйте PostgreSQL connection string. Он должен содержать параметр `sslmode=require`. Считайте эту строку паролем — не публикуйте её.
4. Опубликуйте папку проекта в отдельный репозиторий GitHub. Не загружайте `.env` или `node_modules`; `.gitignore` уже исключает их.
5. В Render создайте **New → Web Service** и подключите репозиторий GitHub.
6. Используйте настройки: Build Command `npm install`, Start Command `npm start`, Runtime `Node`, план `Free` (для учебной демонстрации).
7. В Environment Variables добавьте `DATABASE_URL` и вставьте connection string из Neon. Добавьте переменную `NODE_ENV` со значением `production`.
8. Нажмите Deploy. После публикации откройте URL Render, а затем URL `/api/health`. Ожидаемый ответ: `{"status":"ok","database":"connected"}`.

Локальный `.env` оставляйте только на собственном компьютере. Не вставляйте строку `DATABASE_URL` в публичные файлы, сообщения или репозиторий GitHub.
